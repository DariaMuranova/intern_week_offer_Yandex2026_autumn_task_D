# Древние автомобили: предсказание траектории по векторной карте

Репозиторий содержит полностью воспроизводимое решение задачи предсказания 46 будущих точек траектории автомобиля. Весь pipeline — чтение исходных CSV, построение признаков, spatial validation, обучение моделей, подбор ансамбля, переобучение на всех данных и создание `submission.csv` — находится в одном notebook:

- `ancient_cars_solution.ipynb`

Финальное решение — ансамбль двух graph-attention моделей:

1. Большая модель на 19,0 млн параметров.
2. Малая модель на 4,1 млн параметров, дополнительно обученная с masking-регуляризацией векторной карты.

Итоговые веса ансамбля:

| Компонент | Вес |
|---|---:|
| Big Graph Attention | 0.547981 |
| Fine-tuned Small Graph Attention | 0.452019 |

## Результаты валидации

Главная проблема этой задачи — сильная географическая утечка при случайном разбиении. Соседние сцены часто содержат одинаковые или почти одинаковые фрагменты карты. Поэтому обычный random split показывал нереалистично низкий ADE около 1.6–1.8, хотя такие модели получали больше 3 на скрытом тесте.

В решении используется spatial split по ячейкам 100 × 100 метров. Все сцены одной географической ячейки целиком попадают либо в train, либо в validation.

| Модель | Spatial validation ADE |
|---|---:|
| Исходная Small Graph Attention | 3.175375 |
| Small Graph + map masking fine-tune | 3.109345 |
| Big Graph Attention | 3.047871 |
| Big + Fine-tuned Small, полный holdout | **2.885229** |
| Big + Fine-tuned Small, 5-fold OOF | **2.885715** |

Вес большой модели на пяти внутренних folds менялся только от 0.5336 до 0.5584. Это важная проверка: выигрыш ансамбля стабилен и не является случайной подгонкой весов к одному holdout.

Точное значение приватного leaderboard в репозитории не фиксируется. В таблице приведены только метрики, которые можно воспроизвести локально.

## Постановка задачи

Одна строка датасета соответствует одной дорожной сцене. Поля `x`, `y`, `dir_x`, `dir_y` и `types` описывают векторную карту:

- `x`, `y` — координаты начала дорожных векторов;
- `dir_x`, `dir_y` — направление вектора;
- `types == 15` — граница полосы;
- `types == 16` — центральная линия полосы;
- `target_point` — приблизительная цель маршрута;
- `target_x`, `target_y` — 46 будущих точек, присутствуют только в train.

Метрика — средняя евклидова ошибка по 46 точкам:

```text
ADE = mean_t sqrt((target_x[t] - pred_x[t])² + (target_y[t] - pred_y[t])²)
```

Затем ADE усредняется по всем сценам.

## Почему случайная валидация не работает

При split вида `row_index % 5` ближайшая обучающая сцена для половины validation имеет практически нулевое расстояние по глобальным координатам. На test распределение другое: медианное расстояние до ближайшей сцены около 30 метров.

Используемый split:

```python
cells = floor(global_xy / 100)
cell_hash = cell_x * 73856093 ^ cell_y * 19349663
validation = cell_hash % 5 == 0
```

Для него распределение расстояний до train почти совпало с test:

| Выборка | q10 | q25 | q50 |
|---|---:|---:|---:|
| Spatial validation | 26.39 | 28.46 | 30.73 |
| Test | 26.45 | 28.35 | 30.96 |

Все решения в notebook выбираются только по этому split.

## Представление сцены

### Локальная система координат

Для каждой сцены строится локальный базис:

- начало — `(x[0], y[0])`;
- продольная ось — первый корректный вектор направления;
- поперечная ось — перпендикуляр к продольной.

Карта, `target_point` и траектория переводятся в этот базис. Координаты карты делятся на 100, а направление остаётся единичным. Благодаря этому модель не запоминает абсолютные координаты города.

Важно: первая точка траектории не равна `(x[0], y[0])`. В train среднее расстояние между ними около 4.9 метра, поэтому принудительное обнуление первой точки ухудшает результат.

### 512 map-токенов

Из карты выбираются четыре блока по 128 уникальных векторов:

1. ближайшие к локальному началу;
2. ближайшие к `target_point`;
3. ближайшие к коридору от начала до цели;
4. равномерно выбранные по исходному порядку.

Один токен содержит пять чисел:

```text
[local_x / 100, local_y / 100, local_dir_x, local_dir_y, type - 15]
```

Повторное использование одного вектора в разных блоках запрещено. Недостающие позиции заполняются нулями.

### Граф карты

Для каждого токена заранее находятся восемь ближайших соседей через `scipy.spatial.cKDTree`. Индексы соседей сохраняются в NPZ-кэш, поэтому во время обучения дерево не перестраивается.

### Контекст сцены

Дополнительный вектор из шести признаков:

```text
[goal_along / 100,
 goal_lateral / 100,
 goal_radius / 100,
 goal_available,
 map_vector_count / 4000,
 centerline_fraction]
```

## Архитектура

### Кодирование токенов

Координаты дополняются Fourier-признаками с частотами `[1, 2, 4, 8]`. К ним добавляются embedding источника блока и позиции внутри блока.

### Graph message passing

Каждый graph-слой выполняет attention по восьми соседям. Attention bias вычисляется из разности исходных признаков пары токенов. Это позволяет модели учитывать расстояние, относительное направление и тип соседних дорожных элементов.

### Latent cross-attention

Набор обучаемых latent-токенов несколько раз читает всю карту через cross-attention. Затем 46 временных запросов декодируют будущую траекторию, используя latent-токены и map-токены как общую память.

### Размеры моделей

| Параметр | Small | Big |
|---|---:|---:|
| Width | 192 | 384 |
| Graph layers | 4 | 6 |
| Graph heads | 6 | 8 |
| Latent tokens | 28 | 48 |
| Decoder heads | 8 | 8 |
| Dropout | 0.06 | 0.10 |
| Параметров | 4,056,794 | 19,041,650 |

## Функция потерь

Основной loss — ADE в метрах. Дополнительно штрафуется ошибка скоростей соседних точек:

```text
loss = ADE + 0.08 * MSE(pred_velocity, target_velocity)
```

Для большой и fine-tuned малой модели добавлен слабый штраф кривизны:

```text
loss += 0.02 * MSE(pred_second_difference, target_second_difference)
```

Нормализация target используется только внутри сети. ADE всегда вычисляется после обратного масштабирования, в метрах.

## Регуляризация map masking

Во время обучения случайно скрывается часть map-токенов:

- 6% для Big Graph;
- 8% при fine-tune Small Graph;
- восемь ближайших к началу токенов никогда не скрываются;
- validation и test всегда используют полную карту.

Этот fine-tune улучшил Small Graph с 3.1754 до 3.1093. Простая геометрическая постобработка почти не помогала: проекция на центральную линию, сглаживание и притягивание к `target_point` давали менее 0.01 ADE.

## Схема обучения без утечки

Обучение проходит в два независимых этапа.

### 1. Выбор конфигурации и числа эпох

На spatial split обучаются модели и сохраняется лучший checkpoint:

- Small base: 180 эпох;
- Small masking fine-tune: лучший результат после 55 дополнительных эпох;
- Big: лучший результат на 185-й эпохе из 220.

После этого веса ансамбля оцениваются пятифолдовой OOF-проверкой внутри spatial holdout.

### 2. Финальное обучение

Модели создаются заново и обучаются на всех 12 300 сценах:

- Small base — 180 эпох;
- Small fine-tune — ещё 55 эпох;
- Big — 185 эпох.

Validation-checkpoint не используется для test. Из него берутся только архитектура, гиперпараметры и число эпох.

## Запуск

### Требования

- Python 3.11 или 3.12;
- CUDA-совместимая видеокарта;
- рекомендуется 24–32 GB VRAM;
- около 12 GB свободного места для данных, кэшей и checkpoint;
- исходные `train.csv` и `test.csv`.

Проверенная конфигурация:

- NVIDIA RTX 5090 32 GB;
- Python 3.12;
- PyTorch 2.7;
- CUDA/BF16.

### Установка

```bash
python -m venv .venv
source .venv/bin/activate          # Linux/macOS
# .venv\Scripts\activate         # Windows PowerShell
pip install -r requirements.txt
```

Положите файлы в:

```text
data/train.csv
data/test.csv
```

Запустите:

```bash
jupyter lab ancient_cars_solution.ipynb
```

Выполните клетки сверху вниз. Клетка конфигурации содержит пути, seed и переключатели стадий. Извлечение признаков выполняется один раз; при повторном запуске используются NPZ-кэши.

## Оценка времени

На RTX 5090:

- извлечение признаков — несколько минут;
- Small spatial/full run — около 25–30 минут;
- masking fine-tune — около 8 минут;
- Big spatial run, 220 эпох — около 66 минут;
- Big full run, 185 эпох — около 67 минут.

Полное воспроизведение с validation и финальным обучением занимает несколько часов. Notebook сохраняет resume-checkpoint каждые пять эпох.

- координаты возвращены из локальной системы в глобальную.

## Что не сработало

### Random split

Давал ADE около 4.6–4.8 из-за почти дублирующихся соседних сцен. На скрытом test такие решения не проходили порог 3.

### ExtraTrees и обычный MLP

На realistic spatial split ExtraTrees давал около 4.1 ADE. MLP хорошо выглядел только на split с утечкой.

### Предсказание четырёх узлов

Oracle с известными истинными четырьмя узлами даёт ADE около 3.82, но модель недостаточно точно предсказывала сами узлы. Отдельная four-knot attention модель получила около 3.66.

### Отражение карты

Left-right test-time augmentation ухудшило ADE до 8+. Каноническая сторона дороги содержит полезную информацию, поэтому принудительная симметрия неверна.

### Простая геометрическая коррекция

Сглаживание, притягивание конца к `target_point` и проекция на ближайшую центральную линию почти не меняли метрику. Главная ошибка находилась в выборе формы маршрута в середине траектории.

## Воспроизводимость

- Зафиксированы seed Python, NumPy, PyTorch и CUDA.
- Используется BF16 autocast и `GradScaler`.
- Scheduler и число эпох финального обучения совпадают с validation run.
- При resume восстанавливаются веса, optimizer, scheduler, scaler и RNG states.
- Веса ансамбля подбираются только на out-of-sample spatial predictions.

Небольшие расхождения возможны между версиями CUDA, драйверами и GPU из-за недетерминированных attention kernels.
